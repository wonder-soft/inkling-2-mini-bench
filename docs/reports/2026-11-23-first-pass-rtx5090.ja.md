# 第1回計測：RTX 5090 ×1（2026-11-23）

## 結論

1. **コーディングは同じクラスの比較対象より明らかに強い。とくに Rust。** 同じタスク・同じ量子化クラス・同じカードで、Rust の pass@1 が **5/5**（effort 0.2）。Qwen3.8-27B と Qwen3.6-27B は 0/5、DeepSeek-V4-Flash 284B は 2/5 だった。Go と Python も 5/5。
2. **thinking は「上げるほど悪くなる」。既定の 0.9 は使わない方がよい。** effort 0.2 が最も速く、正解率も最も高い。0.9 以上では推論が止まらず、上限トークンを使い切って回答が空になる例が繰り返し出た（下の A5）。**OpenCode では 0.2 を推奨。**
3. **Scala は 1 発では通らない（0/5）が、修復ループでは収束する（3 ラウンド目でテストまで通過）。** Qwen3.6-27B は同じ修復ループで収束しなかった。
4. **OCR は合成した請求書で誤りゼロ**（文字起こしも項目抽出も全問正解）。Tesseract 単体は CER 11.5%。ただし縦書きの数値には**暗記による水増し**がある（後述）。
5. **速度：デコード 94 tok/s、TTFT 0.14 秒。** 同じカードの Qwen3.8-27B（68 tok/s、0.52 秒）より速い。
6. **弱点：tool の選択精度が 60%。** 書き込みや実行を頼まれても、まず `list_dir` で下見をしにいく。不正な tool 呼び出しはゼロ。エージェントのループは 10/10 で解決。
7. **32GB に載るコンテキストは 131k まで**（vision 込みで VRAM 31.9GB）。262k はメモリ不足で起動できない。公称の 1M には遠い。

### B6. effort 0.9 の OCR

先頭の8枚（全部が請求書）で CER 0.0%。所要時間は 9.1 秒 → 13.2 秒。**この課題では推論を増やしても得るものがない。** 縦書きは測っていない。

### OCR の結果を読むときの注意（重要）

- **縦書きの文は『吾輩は猫である』の冒頭で、モデルが暗記している。** 文字だけで「冒頭を書いて」と頼むと、一字一句そのまま書けた。縦書きの CER は、読めているかどうかではなく暗記で埋めている可能性がある。次回は有名でない文に差し替える。
- 合成した文書はフォントで描いたきれいな画像（Noto CJK）で、劣化も弱い。実際にスキャンした書類や手書き、複雑な表は測っていない。
- 縦書きは1文字ずつ描いており、縦書き用の字形を使っていない（`ー` と `。` が横書きの形のまま）。本物の縦組みより易しい。
